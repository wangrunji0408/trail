# 衔尾：机制设计 v2

本文面向创作者，含剧透与技术术语。游戏界面不出现 agent、LLM、token、context、harness 或 skill。

## 当前交互

初始蛇只有头、尾两格。果纹是当前可用的信息块，输入与输出都占身体容量。

- 方向键移动一格，接触果子时读取输入。
- 花台、石碑、水井、书卷、开关、陶壶都在接触时自动生效。
- **空格沿当前朝向前进一步，并根据已有果纹输出一枚新果纹。** 输出直接进入蛇身，原输入保留；地图不会出现输出物品。
- 输出与这次移动是一个原子步骤；撞墙、撞身或容量不足时两者都不发生。Z 同时撤回移动、输出与自动机关效果。
- 当前不设计思考机制，也没有思考气泡、等待时间或额外资源。

界面只保留目标、容量、操作、配方及具体事件结果。机关不标注名称，也不在侧栏说明解法。提示牌全部位于角落，默认通关路线不触发；提示只透露一条规则性质，不给路线和操作顺序。

## 状态关系

| 机制 | 技术隐喻 | 边界 |
| --- | --- | --- |
| 吃果留纹 | 输入加入当前上下文 | 曾经吃过不等于现在仍可用。 |
| 有限容量 | 上下文预算 | 无关输入和新输出都占空间。 |
| 三红果折一红印 | 有损压缩 | 保留颜色，不能代替井所需的鲜果。 |
| 独立石碑 | 持久化写文件 | 每个坐标独立保存，必须回到原位置读取，不共享或传送。 |
| reset 门 | 清空当前上下文 | 保留地图、石碑与已开启机关；不会自动开门。 |
| 右侧独立开关 | 改变环境状态 | 先穿 reset 到右边，才可开启返回左边的回路。 |
| 自动投入井 | 工具调用和返回 | 工具返回先在外部世界，读取后加入身体。 |
| 空格输出并前进一步 | 生成内容也进入上下文 | 不消耗已有输入，需要为新输出留容量。 |
| 配方卷 | 渐进式披露与 skill 按需加载 | 先只见卷名，实际读取后展开并启用规则，规则自身占一格。 |
| 陶壶 | 隔离子任务 | 父房间暂停，子房间从两格开始，只返回花种。 |

玩家承担决策，确定性引擎执行环境规则。果纹是信息块，而非字面 token；原型不模拟概率采样或真实模型推理。

## 九关

1. **初尝**：红果与红门，建立输入改变可行动作的联系。角落提示「门只检查蛇身上的果纹」。
2. **恰好**：两格容量，直路是无关金果，上路是目标输入。
3. **折叠**：吃下三红果后需要两颗月果；花台在上方支路，玩家要主动绕过去压缩。
4. **储物**：左侧只有一块石碑。保存后穿 reset 到右侧，踩右侧开关打开回路，再回原碑读取。携带内容从已打开的机关门离开。reset 不联动开门，机关上不写名称。
5. **水井**：花台故意位于惯性直路；第三颗红果所在处留绕行口。直走会自动压缩成红印，随后不能投入井，反转上一关经验。井顶始终以图案显示鲜红果 → 月果。
6. **新果**：基础配方红色 + 月果 → 金果。空格输出金果到蛇身并向前一格，输入保留。出口验收蛇身上的金果，没有输出方框或地图产物。
7. **配方卷**：仅凭月果、金果不能输出花种。未读时只显示花种卷标题；碰触后展开月果 + 金果 → 花种，卷本身占一格。四格容量容纳书卷、两项输入和一项输出。
8. **陶壶**：碰触自动进入，父房间保持。壶内有自己的身体和容量，只返回一枚花种。返回后不会再次自动进入，只有下一次移动才触发碰触。
9. **组合**：压缩、原地保存、reset、右侧开关、回原碑读取、壶内花种、月果输入、空格输出金果。四格容纳红印、月果、花种和金果，出口验收其中三种。此顺序只在本文，不出现在提示牌中。

## 提示与配方

提示牌只是可选线索，不授予能力，不占身体。例如储物关只写「石碑中的物品，不会随蛇身一起消失」。所有提示牌的合法访问路线都有测试；九条默认通关路径均不经过它们。

配方卷是可执行规则，不是提示牌。未读取的正文不进入可见界面或隐藏弹层。加载后正文与生成规则一起可用，占一格；容量满则不能加载。是否可生成取决于当前身体内的规则与原料。

## 持久化、撤回与验证

石碑以坐标保存一枚果纹，写入不移走原物，读出不擦掉记录。开关以通道记录开启状态，reset 不更改记录。当前关的一切状态都可按整步撤回，包括空间切换。

浏览器仅按稳定关卡 ID 保存所在关与已通关记录；刷新或重来会重置当前谜题。输入、输出均立即改变容量；输出前进一步时身体同时增长。子房间返回的额外尾节在接下来的移动补齐。

30 项测试覆盖九关通关、所有角落提示牌可达、默认路线不触发提示、独立石碑、reset 与开关解耦、惯性压缩失败、输出不消耗输入且不产生地图物品、输出步原子回滚与撤回、输出步直接通关、按需加载配方、自动进壶与只返回成果。
